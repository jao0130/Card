滾動機率流程

每抽一張都重新讀取目前收藏，只排除 N 到 UR 的已飽和卡片；EPIC 與 LR 不設限，會保留在卡池中，再把剩餘可抽稀有度權重正規化。

1

讀取卡包

取得目前 pack 內所有卡片。

2

排除飽和

N 到 UR 若 count >= limit 就移出池；EPIC/LR 保留。

3

重算權重

只有仍有卡片的稀有度參與抽選。

4

即時更新

10 連抽途中也會逐張更新飽和狀態。

若 N/R 滿池：LR 有效機率約 5.1% EPIC/LR 不會因張數飽和移出 機率 UI 顯示目前有效機率

翻卡音效 Bug 修法

A

Session ID

每次揭曉建立 revealSessionId。

B

Timer Registry

所有 timeout 透過 scheduleRevealTimer 登記。

C

Cancel

關閉、重抽、切頁清空 timers 並讓舊 callback 失效。

D

Stop SFX

停止 cardFlip、newCard、legendary、packOpen 等音效。

抽卡動畫標準

0.0s

撕包、暗場、舞台光收束。

0.4s

卡片分批進場，保持固定尺寸避免跳版。

Flip

新卡與高稀有卡增加停頓、spotlight、rim glow。

LR

傳說卡進入完整 Showcase overlay。

效能約束

  • 動畫優先使用 transform / opacity。
  • overlay inactive 時停止粒子與無限動畫。
  • 手機降低粒子數、blur 和 drop-shadow 疊加。
  • 支援 prefers-reduced-motion。
  • 預載當前抽卡結果，不預載整個素材庫。

驗證清單

  • 關閉 overlay 後翻卡、新卡、傳說音效全部停止。
  • 重抽前會取消上一輪 reveal timers。
  • N 到 UR 的飽和卡不再被抽到。
  • 10 連抽中途達上限會即時排除受限稀有度。
  • 有效機率 UI 會跟著剩餘卡池更新。
  • 若沒有任何可抽卡，不能繼續 OPEN。
  • 訪客模式無 Supabase 也能玩。
  • 登入後本機與雲端收藏加總，只 clamp N 到 UR。
  • 手機 viewport 不重疊、不跳版。
  • npm run build 通過。
